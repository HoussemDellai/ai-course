Le dossier du trimestre: la dépréciation de Nginx Ingress Controller

Le SIG Network de Kubernetes et le Security Response Committee ont annoncé la retraite d’Ingress NGINX avec fin de maintenance en mars 2026 . Aucune action immédiate n’est requise pour les clusters AKS utilisant l’add-on Application Routing avec NGINX. Microsoft assurera le support officiel jusqu’en novembre 2026 (limité aux correctifs de sécurité critiques).

Microsoft investit dans l’avenir de la connectivité applicative d’AKS autour de la Gateway API : support dans le service mesh Istio, extension de l’add-on Application Routing pour la Gateway API, et poursuite des investissements dans Application Gateway for Containers.

L’Application Routing avec Gateway API, pilotée par un plan de contrôle Istio pour l’ingress basé Gateway API uniquement, est prévue au 1er semestre 2026 avec documentation de migration.
Les utilisateurs d’Ingress NGINX peuvent migrer vers l’add-on service mesh Istio (Gateway API) ou vers Application Gateway for Containers (via Ingress API ou Gateway API) (source).

Lorsque vous abordez cette discussion avec vos clients, faites attention au fait que AGC ne supporte pas encore la private IP pour une exposition privée. Une solution pourrait être d'utiliser à la fois AGC pour l'exposition publique et aussi Envoy Gateway (compatible Gateway API) pour l'exposition privée tant qu'on peut se passer du WAF pour le trafic interne. Le jour où la prise en charge de Private IP sera disponible dans AGC, on pourra facilement migrer Envoy Gateway vers AGC.

Si vous avez des clients qui posent des questions à ce sujet, n'hésitez pas à vous rapprocher des SME containers.

Azure Kubernetes Service

AKS peut hoster des serveurs MCP à travers KAITO en se basant sur vLLM (GA).

Afin d'améliorer la latence réseau du trafic entre les pods, AKS avec CNI Cilium rajoute un mode Local redirect policy permettant de favoriser le trafic entre pods du même node quand c'est possible. Evitant ainsi le trafic inter-node ou même pire inter-région (GA).

Les policies de type cluster-wide sont enfin supportées. Cela permet de définir des policies couvrant plusieurs namespaces, au lieu d’en définir une par namespace. (GA).

A travers la fonctionnalité payante de ACNS, les network policies niveau 7 sont maintenant supportés. Ca permet de ne pas se limiter au niveau 4 comme c'est le cas sans ACNS et de pouvoir définir des contrôles au niveau application (GA).

AKS Automatic offre la possibilité de gérer même le nodepool système (scaling, update, etc). Ca fait moins de responsabilité, lourde quand même, à gérer dans un cluster (Public Preview).

Support de Windows Server 2025 arrive sur AKS.
On vous dit notre avis. Nous, non, nous n'aimons pas le niveau de support Windows dans AKS. C'est au moins 5 ans de retard qui ne sera jamais rattrappé par rapport au Linux containers. Toujours des problèmes d'incompatibilité avec les outils. On ne conseille pas nos clients de l'utiliser. S'ils veulent vraiment des containers Windows, ils peuvent le faire soit sur App Service soit sur ACI (Public Preview).

Managed namespace est passé en GA. C'est le moyen de créer une expérience Namespace as a Service pour les équipes de développement. Le namespace pourrait être crée et géré au niveau Infra as Code avec Bicep ou Terraform (GA).

Pod sandboxing se base sur Kata-Containers pour améliorer la sécurité des containers. Il isole chaque container cible dans une VM dédié! Cela évite les problèmes d’interférences entre pods (GA).

Azure Container Apps

Nous constatons des efforts soutenus de la part des équipes ACA visant à faire d’ACA le service managé le plus simple pour les applications d’IA. La plateforme exécute les Agents Foundry en modes isolé et public, et le support des serveurs MCP ne cesse de se renforcer. En outre, une intégration avec Docker Compose est en cours, afin de permettre l’orchestration des agents, des LLM et des serveurs MCP via un unique fichier Compose dans ACA.
 
Les dernières nouveautés annoncées à Ignite :
Premium Ingress est maintenant disponible en GA permettant de configurer l’ingress au niveau de l’environnement. Avec un ingress Premium, vous pouvez définir comment l'ingress est dimensionné et configuré pour mieux gérer les fortes charges de travail (GA)

Rule-based routing est maintenant disponible en GA. Cette fonctionnalité permet de rediriger le trafic HTTP en fonction du nom d’hôte ou du chemin d’URL, offrant plus de flexibilité pour les architectures microservices, les déploiements A/B ou blue‑green (GA)

Confidential computing en public preview apporte des environnements d’exécution de confiance (TEE) aux workloads ACA (Public Preview).

Flexible workload profile: un nouveau type de profile qui se rajoute à Comsumption et Dedicated. Il permet d'avoir le meilleur des deux mondes: le modèle de pricing du mode Consumption et le contrôle sur la configuration network et SKU des nodes du mode Dedicated (Public Preview).

Support de agentic Docker Compose permettant de lancer tous les composants d'un agent IA, à voir le modèle LLM, serveur MCP, sessions dynamiques à travers un seul fichier Docker-Compose sur une infra contenant du GPU (Public Preview).

Azure Fleet Manager
Fleet manager permet maintenant d'attacher et gérer les clusters géré par ARC-enabled cluster. C'est utile pour gérer ses clusters on-premises à travers Fleet manager (Public Preview).

Azure Container Registry
Pas de nouveauté majeure pour ACR. Pour rappel, ACR permet maintenant de gérer les rôles RBAC au niveau des images. Donc plusieurs équipes peuvent se partager le même registry et chacune aurait accès uniquement à ses propres images (GA).

Azure Application Gateway for Containers

AGC s'intègre maintenant avec Istio Service Mesh afin de gérer le trafic ingress (Public Preview).

Support d'un Slow Start permettant de réduire le trafic à envoyer sur les nouveau pods fraichement crée suite à un événement d'auto-scaling. Cela permet d’éviter de perturber les pods qui font du cold-start (GA).

Notre partenaire du trimèstre: NetApp

Azure NetApp Files (ANF) est un service de stockage Azure offrant des performances garanties, une latence ultra-faible et une élasticité instantanée, sans tuning ni gestion d’infrastructure.


ANF fournit du NFS/SMB natif enterprise, idéal pour les workloads containers stateful les plus exigeants sur AKS.


Avec Astra Trident (gratuit et supporté par NetApp), les volumes sont provisionnés dynamiquement en quelques secondes, accélérant fortement le time-to-market.
Snapshots instantanés, haute disponibilité intégrée et montée en charge à la volée font d’ANF un accélérateur de fiabilité et d’agilité.


C’est ce différentiel qui séduit des acteurs comme SNCF pour leurs plateformes containers critiques.

 Nouvelle version Kubernetes
Tout les quatre mois, on sort une nouvelle version. Publié le 17 décembre 2025, Kubernetes v1.35 a vu le jour avec une dizaine d'améliorations majeures. D'habitude AKS intégre les nouvelles versions en Preview dans un mois. Voici les nouveautés les plus importantes.
             
Kubernetes v1.35 rend la tolérance du HPA configurable par ressource (champ behavior), remplaçant le seuil global et fixe de 10 % pour ajuster finement la sensibilité du scaling (p. ex. 0,05).
Kubernetes passe les mises à jour in‑place des ressources des Pods en GA, permettant d’ajuster CPU/mémoire sans redémarrer et évitant la recréation des Pods, pour un scaling vertical plus fluide, non disruptif et efficace.
Mise à jour de trafficDistribution pour les Services : ajout de PreferSameNode (privilégie les endpoints du node local) et renommage de PreferClose en PreferSameZone avec rétrocompatibilité, clarifiant les préférences de routage au niveau node vs zone.
Kubernetes v1.35 promeut l’exposition des labels de topologie (zone/région) via le Downward API : le kubelet les injecte dans les Pods, rendant les apps topology‑aware sans dépendre de l’API ni de larges RBAC. Et c'est à travers les variables d'environnements.



Côté Open source

Docker publie en open source son catalogue de plus de 1000 Docker Hardened Images. Ils offrent une base d’exécution durcie et distroless qui réduit jusqu’à 95 % des vulnérabilités par rapport aux images communautaires, tout en conservant les outils essentiels pour les développeurs. Elles s’appuient sur Debian et Alpine pour éviter tout lock‑in et s’intégrer avec un minimum de changements aux workflows existants (source).
Crossplane atteint le statut Graduated: En novembre 2025, ce projet de control plane multi-cloud open source a officiellement gradué au sein de la CNCF, signe d’une adoption large et d’une maturité accrue. Avec plus de 3 000 contributeurs, la version 2.0 récente s’impose comme brique clé du platform engineering pour piloter des infrastructures par API déclaratives (source).
Docker Compose évolue pour orchestrer des architectures d’agents (modèles + outils) dans les mêmes fichiers YAML (docker compose), du local au cloud.

On peut définir agents/modèles/outils comme services, exécuter localement ou déployer sur Cloud Run / Azure Container Apps, avec intégration MCP Gateway pour une découverte/communication sécurisée (source).

AWS 

EKS Capabilities : AWS a lancé une suite de services managés intégrant des outils open source populaires comme Argo CD (GitOps) et AWS Controllers for Kubernetes (ACK), facilitant la gestion des ressources AWS via les API Kubernetes (source).

ACK est l'équivalent de notre Azure Service Operator (ASO) qui est sorti depuis 4 ans. Mais il a beaucoup du mal a être utilisé par nos clients faute du concept de créer des resources cloud depuis un cluster Kubernetes. Schneider l'utilise à petit échel et sont toujours effrayé d'un potentiel fin de support.

Automatisation pour l’IA : Avec EKS Auto Mode et le support de clusters jusqu’à 100 000 node, AWS cible les charges de travail IA à grande échelle, en simplifiant l’autoscaling GPU et la gestion des ressources (source).

GCP

Agent Sandbox (préversion) : bac à sable kernel basé sur gVisor pour exécuter en sécurité des agents IA et code non fiable sur Kubernetes, avec démarrage en quelques centaines de ms, snapshots et optimisations hôte.

Scalabilité record : GKE a fait tourner un cluster Kubernetes de 130 000 nodes (doublant le précédent record), grâce à des optimisations API server / etcd / Spanner et Kueue. Bénéfices généralisés + MultiKueue et Image Streaming pour accélérer les déploiements multi‑clusters (source).

GKE Inference Gateway est une extension du GKE Gateway qui offre un routage et un load balancing optimisés pour les workloads d’inférence IA générative. Il simplifie le déploiement, la gestion et l’observabilité des services d’inférence (source).

llm-d est une plateforme d’inférence distribuée nativement Kubernetes qui fournit des “parcours balisés” (recettes testées + Helm charts) pour déployer et faire évoluer rapidement des modèles génératifs de grande taille avec des performances SOTA sur divers accélérateurs et clouds. IBM et Redhat sont également contributeurs (source).

Comment générer davantage d’ACR grâce aux conteneurs ?
Deux sujets clés peuvent être abordés avec vos clients et constituent d’excellentes portes d’entrée pour générer de l’ACR : NGINX Ingress et Azure NetApp Files (ANF).
NGINX Ingress
De nombreux clients Kubernetes s’appuient encore sur NGINX Ingress qui est déprécié. Cette frustration est une véritable opportunité pour positionner des alternatives Microsoft, telles qu’Azure Application Gateway, ou mieux encore Application Gateway for Containers, qui offre une intégration native avec AKS, des fonctionnalités avancées de sécurité et une meilleure observabilité.
Azure NetApp Files (ANF)
ANF représente un levier majeur pour générer de l’ACR en proposant des options de stockage hautes performances adaptées aux workloads conteneurisés et aux applications critiques. Comparé à Azure Files, ANF apporte des gains significatifs en termes de latence, de débit et de fonctionnalités avancées (snapshots, scalability, performance tiers), ce qui permet de répondre à des exigences applicatives plus élevées.
Enfin, il est important de rappeler que la vente de ces solutions via la Marketplace contribue directement à l’ACR, renforçant ainsi l’impact business de ces discussions techniques.
